# iCode 对标差距分析报告（2026-08-29）

> 对标对象：**CLI / TUI / UI** → Claude Code、OpenCode、Reasonix；**桌面版** → Reasonix 桌面、WorkBuddy（腾讯 CodeBuddy Work）。
> 结论先行：上一轮（2026-08-11）差距分析中的 P0/P1/P2 已全部落地（v0.47.3 收官）。当前 iCode 在**能力广度**（72+ 斜杠命令、38 个工具、13 个 Provider、hooks、技能市场、自动化、checkpoint、mesh）上仍是五者中最全；剩余差距已从「功能有无」转移到四类：**并发与多会话、桌面 Git 工作台、生态分发（分享/市场/ACP）、无人值守深度**。另有两个纯质量项（英文 i18n、自动更新）。

## 二、CLI/UI 端差距（对标 Claude Code / OpenCode / Reasonix）

### C1 · 会话分享链接（对标 OpenCode `/share`）— 建议 P1

- **现状**：`/share` 仅本地 Markdown 导出变体，无公网分享链接。
- **OpenCode**：`/share` 生成公开 URL，会话托管在其服务器可随时取消分享。
- **建议**：走「本地单文件 HTML」路线差异化——导出自包含 HTML（内联 CSS/JS 渲染 Markdown、代码高亮、工具调用卡片），用户自行粘贴到任何静态托管/网盘；不建服务器（开源项目无后端成本，也规避隐私风险）。CLI `/share html` + 桌面一键导出。
- **成本**：1 天（复用现有 Markdown 渲染逻辑转 HTML 模板）。

### C2 · Git-backed 会话回放（对标 OpenCode v1.3.0）— 建议 P2

- **现状**：会话存 SQLite；checkpoint 快照与 git 分离。
- **OpenCode**：会话以 git 提交序列存储，可直接 diff 任意两次会话、review 无需 `git status`。
- **建议**：不必改存储结构（改动过大）。做 `/replay`：按时间轴列出本会话每次文件修改（数据源 checkpoint 已有），支持 `选中两个点 → DiffViewer 对比`。增量小、体验接近。
- **成本**：1-2 天。

### C3 · ACP（Agent Client Protocol）编辑器接入（对标 Reasonix）— 建议 P2

- **现状**：VS Code 扩展走自有 HTTP 协议；其他编辑器（Zed、Neovim）无法接入。
- **Reasonix**：`reasonix acp` 任何 ACP 编辑器可连，VS Code 扩展走 Open VSX + Marketplace 双渠道。
- **建议**：实现 ACP stdio 服务端（会话/权限/diff 事件映射到现有 engine），收益是「一份协议接入 N 个编辑器」。同时把现有 VS Code 扩展发布到 Open VSX。
- **成本**：3-5 天（协议适配层）。

### C4 · Hooks 事件继续补齐（10 → 20+）— 建议 P2

- **现状**：10 种（v0.47.1 补齐了 Session/Permission/Subagent 系列）。
- **Claude Code**：约 30+ 种，还包括 SessionEnd、工具失败（PostToolUse 带 error 分支）、MCP 服务器生命周期、压缩完成 PostCompact、Telemetry 等。
- **建议**：补 5-8 个高价值事件即可：`SessionEnd`、`PostCompact`、`ToolError`、`AgentStart/Stop`（主循环级）、`ConfigChange`。其余低频事件不必追平。
- **成本**：1 天（分发框架已就绪，纯加事件）。

### 暂不建议（对标存在但价值/成本不匹配）

- **Claude Code Web/iOS 远程接管**：需要官方云服务，开源项目无法复刻；现有 /remote + mesh 已覆盖局域网场景。
- **OpenCode Zen 托管模型服务**：商业服务，非客户端功能。
- **Reasonix 的「仅 DeepSeek」单模型策略**：与 iCode 多模型定位相反，无需跟进。

## 三、桌面端差距（对标 Reasonix 桌面 / WorkBuddy）

### D1 · 多会话并行流式（对标 OpenCode 多会话 / Claude Code 桌面）— 建议 P1（本轮最高价值）

- **现状**：TabBar 多标签，但**后台标签不流式**——切走即断流，同一时刻只有一个活跃会话。`reorderTab` 拖拽排序是死代码。
- **对标**：OpenCode 卸载式多会话并行（同项目多 agent 同时跑）；Claude Code 桌面后台 subagent 默认并行；Reasonix 桌面 sessions side by side。
- **建议**：
  1. 前端：SSE 连接按会话 ID 索引化（现在绑定活跃会话），后台 tab 各自维持流，完成后通知（系统 toast 已有）；
  2. 顺手接线 `reorderTab`（TabBar 加 draggable，半天）；
  3. 进一步做左右分屏（两会话并排显示，Reasonix 拍照级）——可作二期。
- **成本**：并行流式 2-3 天；拖拽 0.5 天；分屏 1-2 天。

### D2 · Git 工作台面板（对标 Claude Code 桌面 / Reasonix 桌面）— 建议 P1

- **现状**：桌面 git 集成仅剩状态栏分支名展示；diff 能力只存在于 CheckpointPanel（快照回放），**没有工作区 diff 审查 / 暂存 / 提交 / 分支切换 UI**。
- **对标**：Claude Code 桌面每文件 diff 审查 + 提交；Reasonix 桌面核心场景就是「队列任务 → review diffs → 批准」。
- **建议**：新增右侧面板「Git」（与 Todo/Checkpoint/LSP 并列）：工作区变更文件列表（M/A/D 徽标）→ 点击进 DiffViewer（已有，统一转并排渲染）→ 暂存勾选 → 提交框（AI 生成 commit message 按钮，调一次便宜模型）→ 分支切换/新建。后端 git 命令复用 CLI 已有 git_* 工具实现，加 3-4 个 HTTP 端点即可。
- **成本**：2-3 天（DiffViewer 可复用）。

### D3 · 自动化任务模板库（对标 WorkBuddy 杀手锏）— 建议 P0

- **现状**：调度器 + 执行历史 UI 齐备，但**创建任务从零写提示词**，无模板。
- **WorkBuddy**：内置任务模板（新闻推送、周报生成、会议纪要、体检预约、学习计划），用户改两行即可用——这是其「每天省 1 小时」心智的来源。
- **建议**：自动化页加「从模板新建」：内置 8-10 个模板（行业动态早报 / 周报 / 会议纪要 / 代码库巡检 / 依赖更新检查 / 竞品 release notes 摘要 / 朋友圈文案生成 / 知识库日整理……每个 = 名称 + 提示词 + 建议周期），一键套用后仅改关键词。模板存后端（JSON），支持用户自存为模板。
- **成本**：1 天（纯前端 + 一份 JSON）。

### D4 · 办公文档生成技能包（对标 WorkBuddy「自动写 Word/Excel/PPT」）— 建议 P1

- **现状**：技能市场 15 个技能偏开发+运营文案，**无 docx/xlsx/pptx 生成技能**；WorkBuddy 把「自动产出办公文档」当核心卖点。
- **建议**：市场 +3 个技能：`docx-report`（Go 生成 .docx 报告，零依赖可用 Go 库或模板 XML）、`xlsx-sheet`（表格生成/统计）、`pptx-deck`（大纲→幻灯片）。结合现有 image_gen 做封面。差异化点：WorkBuddy 封闭，iCode 技能可自定义。
- **成本**：每个技能 1-1.5 天。

### D5 · 英文 i18n 资源补全 — 建议 P0（质量项）

- **现状**：桌面 `fallbackLng: 'en'` 但**根本没有 en 资源文件**，英文用户看到的是 key 或中文混排；CLI 早已 zh-CN/zh-TW/en 三语。
- **建议**：从 i18n/index.ts 的 zh-CN 提取生成 en 资源（2081 行，一次性翻译），设置页语言下拉解锁 English 选项。
- **成本**：1 天（机械翻译 + 校对）。

### D6 · 桌面自动更新闭环 — 建议 P1（质量项）

- **现状**：CLI 已有 `icode upgrade` 自更新；桌面「自动更新」勾选框**只存配置不执行**，更新页仅手动检查 GitHub release。
- **Reasonix 桌面**：自动检查官方 release 并提示升级。
- **建议**：启动时 + 每日一次静默调 `/api/update/check`（已有），有新版本 → 托盘气泡 + 设置页角标 → 用户确认后调后端复用 upgrade 自更新逻辑替换二进制并重启（Windows 单实例锁与 .old 清理逻辑 root.go:131 已处理）。
- **成本**：1 天。

### D7 · 首跑向导增强（对标 WorkBuddy 安装即用）— 建议 P2

- **现状**：2 步向导（选 Provider → 填 key），无连通性验证、无迁移入口。
- **建议**：第 2 步加「测试连接」按钮（调一次 /api/models 刷新验证 key）；加「从 Claude Code / opencode 导入」（读 `~/.claude/CLAUDE.md`、`~/.config/opencode/` 的配置与指令文件转成 ICODE.md）。
- **成本**：1 天。

### 暂不建议

- **WorkBuddy 的 IM / 小程序端**（微信生态接入）：涉及平台审核与合规，成本极高，且 iCode 的 mesh 已覆盖「多端接管」核心诉求。
- **WorkBuddy 的多专家协同编排画布**（可视化拖拽工作流）：iCode 已有 teams/agents/mesh 文字化编排；画布属于重投入的展示型功能，等用户量上来再说。

## 四、推荐实施顺序（价值/成本比）

| 顺位 | 项 | 理由 |
|---|---|---|
| 1 | **D3 自动化模板库** | WorkBuddy 核心卖点低成本补齐，调度器/历史 UI 已就绪 |
| 2 | **D5 桌面 en i18n** | 质量项，国际用户第一印象 |
| 3 | **D2 Git 工作台面板** | 桌面端「真在干活的 IDE 感」最大缺口 |
| 4 | **D1 多会话并行流式 + 拖拽** | 对标核心体验，CLI/TUI 无法替代的桌面优势 |
