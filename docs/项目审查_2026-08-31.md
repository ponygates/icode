# iCode 项目审查报告（2026-08-31）· 第三轮

> 本轮为**新维度审查**：前两轮聚焦交互/UI 对标 Claude Code，本轮覆盖引擎智能、安全、发布链、配置一致性、代码健康。结论先行：**无 P0 致命项**——安全基线（loopback 绑定/同源校验/DPAPI 密钥加密）扎实，引擎成熟度高于预期（并行只读工具、三态熔断、截断恢复、5 级 token 优化全部实接）。共 20 项发现：**P1×5、P2×14、1 项验证为优**。

## 一、P1（5 项，建议第一批修）

| # | 维度 | 发现 | 建议 |
|---|---|---|---|
| 1 | 引擎 | **工具循环中段无重试/降级**：fallback 链 + 429 退避只包在首轮 Send（engine.go:1893-1960），`continueAgentLoop` 直接裸调 ChatStream（:2142）——工具第 2~10 轮遇 429/配额错误整个回合报废 | 抽取 Send 的 build+retry+fallback 助手，续轮复用 |
| 2 | 引擎 | **续轮丢失 CacheTTL**：首轮带 `CacheTTL: e.cacheTTL`（:1936），续轮请求（:2142-2153）没带——用户配置的 `prompt_cache_ttl` 在首个工具轮之后静默失效。**直接削弱省 token 优势** | 补一行 `CacheTTL: e.cacheTTL` |
| 3 | 安全 | **MCP TrustMode 存而不用**：ask/readonly/all 可配置可显示（handlers_mcp.go:113-149），但 `refreshMCPTools` 无过滤注册（server.go:647-664），权限门零感知——YOLO/auto 下不可信 MCP 写工具不经询问直接执行 | 在 Gate.Check 强制：ask→必询问；readonly→只读白名单 |
| 4 | 安全 | **`/api/files?path=` 接受任意绝对路径**（handlers_files.go:22-39）：全盘目录枚举；配合 #8 的 DNS rebinding 可被跨域读取 | 钳制到活跃工作区根 |
| 5 | 发布 | **CI 发布资产与四二进制方案错位**：`icode-desktop-*` 未加 `-tags desktop_only`（build.yml:199，双击=控制台 TUI）；`icode-cli-*` 是 nogui 无头版而本地同名是 simpleui UI 版；**simpleui 从未进 CI**——与本地刚修过的配方错误同源 | build-desktop 加 tags；新增 simpleui 作业；资产命名区分（icode-simpleui-*） |
