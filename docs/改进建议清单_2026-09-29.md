# iCode 改进建议清单

> 日期：2026-09-29  
> 范围：对照 `ICODE.md`、README、CHANGELOG、CI、三端代码与已知设计文档的只读审查。  
> 状态：**仅建议，未实施**。按编号或批次下令后再改代码。

---

## P0 · 体验与功能缺口

1. **桌面分屏未做完**  
   `SplitPane` 已有，但 `desktop/src/pages/ChatPage.tsx`（约 118KB）仍绑死全局 `activeSessionId`。`docs/split_design.md` 写明：SessionPane 参数化是唯一未完成项，左右会话并排、互不串流还做不到。

2. **巨型前端组件**  
   `ChatPage` / `SettingsPage`（约 83KB）/ `ModelsPage` 体量过大，几乎没有页面级测试（Settings 只有主题切换）。改一处容易伤聊天、权限弹窗、流式、标签。项目自身也把这当成长期健康项。

3. **三端能力不对等**  
   - **VS Code**：轻量侧栏（会话 / 模型 / SSE / 权限 / 选中代码），没有工作区、技能市场、Git 工作台、审查条、多标签分屏。`vscode/README.md` 写明真机未点测。  
   - **TUI**：能力最全，但 Windows IME / 滚轮 / Delete 刚修完一长串，仍依赖真机回归。  
   - **桌面**：功能最多，macOS / Linux 是「托盘 + 浏览器」，不是原生窗。

4. **技能市场仍是本地 catalog**  
   内置约 18 个技能（编码 + 办公 + 保险销售混在一起），导入只能走本机绝对路径。README 里的「社区技能市场」还没做。对外宣传「5 个通用技能」也已经过时。

5. **视频不回灌上下文**  
   `image_gen` 已 base64 回灌 vision；`video_gen` 刻意不回灌。多模态闭环在视频侧是断的。

## P1 · 工程质量

6. **后端巨型文件**  
   `internal/core/conversation/engine.go`（约 102KB）、`slashui.go`、`tui/render.go`、`slash_commands.go`、`cmd/commands.go`、`raw_input.go`、`permission/gate.go`。斜杠命令还在 TUI 与 slashui 两套里，容易漂移。

7. **测试覆盖不均匀**  
   Go 测试包不少（TUI 布局 / 键泵、权限、引擎熔断等较扎实），但：  
   - ChatPage 零测试  
   - VS Code 扩展零测试、CI 也不编 vscode  
   - CI 注释写「coverage gate」，实际只 `cover -func | tail -1`，没有失败阈值  
   - Windows CI：`CGO_ENABLED=0`，race 检测只跑 Linux / macOS

8. **提交物与编码**  
   `vscode/package.json` 中文是乱码（UTF-8 被当错编码），扩展商店展示会难看。`vscode/dist/extension.js` 在 git 里，和「构建产物不入库」不一致。

9. **工作区改动量很大、未收口**  
   审查当时有大量未提交改动（TUI、桌面 ChangedFilesBar、CI、删除 simple UI 等）。没有按主题拆提交 / PR，后续审查和回滚成本高。

## P2 · 平台能力缺口

10. **computer-use / 本地录音仅 Windows**  
    非 Windows 是 stub（「当前仅支持 Windows」）。POSIX 桌面又没有原生窗，computer-use 更难对等。

11. **macOS / Linux 托盘与热键未真机验收**  
    已知：macOS 要辅助功能权限；Wayland 无全局热键，失败只能靠托盘菜单。开发环境在 Windows，交叉 GUI 也验不了。

12. **browser 工具偏弱**  
    是本机 Edge / Chrome `--dump-dom` / 截图，不是可点击、可填表的 agent 浏览器。和 Cursor / Claude 的 browser use 差一档。

13. **LSP / CodeGraph 覆盖窄**  
    LSP 以 gopls 为主、可发现其它 server；CodeGraph 主要是 Go + TS/JS 正则。Python / Rust / Java 等项目里 `code_search` 会明显偏弱。

14. **部分厂商不能实时拉模型**  
    `FetchModels` 主要在 openai_compat / Anthropic；其它厂商会 501「暂不支持 ModelFetcher」。一键刷新模型不是 14 家全开。

## P3 · 文档与版本不一致

15. **热键写错**：`ICODE.md` 亮点仍写 `Ctrl+Alt+I`，代码和设置页已是 **`Ctrl+Shift+Space`**。  
16. **README / ICODE 仍写 v0.1.0**，`version.go` / 桌面 / 扩展已是 **0.1.2**；Roadmap 仍把 CSRF / SSRF / 沙箱标成「下一阶段」，CHANGELOG 里这些已经落地。  
17. **`docs/acp_design.md` 仍写「待实施」**，仓库里已有 `internal/acp`（baseline 有了，权限走编辑器是 P2）。  
18. **Go 版本**：`go.mod` 是 `go 1.25.0` + toolchain `1.26.5`，README 写 1.26+，容易让贡献者搞不清最低版本。

---

## P4 · 安全与产品边界

19. 同源 / CSRF / fetch SSRF / AllowedPaths 已有测试，README 清单过时。仍值得盯的是：loopback HTTP + 本机任意进程可打 API（VS Code / 桌面都靠这个）、mesh 跨机鉴权、YOLO 误触、computer-use 桌面控制面。  
20. 内置技能混入保险话术 / 异议处理，和「开源编码助手」定位容易打架；对外 catalog 是否要分层（coding / office / 垂直行业）需要产品决策。

## P5 · 生态与发布

21. **ACP**：Zed / Neovim 真机接入、权限弹窗、session/load 等按设计文档还没闭环。  
22. **发布**：打 tag 才出多平台二进制；macOS 签名 / 公证、Linux 包格式、VS Code Marketplace 发布都不在当前流水线里。  
23. **扩展安装路径**：README 仍写 `icode-vscode-0.1.0.vsix`，和 package `0.1.2` 对不上。
