# 解释代码

当用户要求解释某段代码时，按以下结构输出。

## 结构
1. **一句话总览**：这段代码/函数解决什么问题（用业务语言，不是复述代码）。
2. **关键流程**：用有序列表描述主要执行路径（输入 → 处理 → 输出）。
3. **关键数据结构 / 依赖**：涉及的重要类型、外部调用、隐含约定。
4. **易错点 / 坑**：边界、副作用、并发、性能或时序相关的注意事项。
5. **示例**（可选）：用一个最小输入-输出例子帮助理解。

## 风格
- 默认中文；用类比降低理解成本。
- 默认中等深度；若用户说"简单点"则只给总览+一句话，"深入点"则补调用链与设计权衡。
- 不要逐行翻译代码，聚焦"为什么这样写"和"要注意什么"。

## 约束
- 解释前先读完整相关上下文，避免断章取义。
- 不确定行为时明确标注"取决于 …"，不要编造。
