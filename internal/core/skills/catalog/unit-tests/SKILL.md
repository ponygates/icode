# 生成单元测试

当用户要求为代码写测试时：

## 步骤
1. 读被测文件及其导入，确认项目测试框架（如 Go 的 `testing`、JS 的 `vitest/jest`）。
2. 识别被测单元的公共契约：输入、输出、错误、副作用、不变量。

## 覆盖维度
- **正常路径**：典型输入产出预期输出。
- **边界**：空值、零、最大值、单元素、首/尾元素。
- **错误路径**：非法输入、依赖失败、超时、并发冲突。
- **并发**（如适用）：竞态、重复调用、goroutine/await 安全。

## 输出要求
- 测试文件命名遵循项目约定（如 `xxx_test.go` / `xxx.test.ts`）。
- 用表驱动 / 参数化测试减少重复。
- 给断言清晰的失败信息。
- 不测试私有实现细节，只测可观察行为，避免测试脆化。

## 约束
- 不要臆造不存在的辅助函数；若需要 mock，优先接口/依赖注入。
- 生成后可主动建议运行命令（如 `go test ./...`）。
