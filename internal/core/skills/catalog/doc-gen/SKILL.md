# 生成文档

当用户要求写/补文档时：

## 类型与结构
1. **代码注释 / docstring**：为导出的函数、类型、包写一句"做什么 + 关键参数/返回值/错误"。不写废话。
2. **模块 README**：目的、安装、最小使用示例、常用 API、注意事项、链接。
3. **API 文档**：每个端点的方法、路径、参数、请求/响应示例、错误码。

## 风格
- 中文优先（项目若是中文仓库）；术语保留英文原词。
- 用示例说话，少抽象描述。
- 保持与代码实际行为一致；写完建议用户核对。

## 约束
- 不要编造不存在的参数或返回值；先读代码确认签名。
- 文档只描述稳定契约，避免写入可能频繁变动的内部细节。
- 不改业务逻辑，只补文档；除非用户要求。
