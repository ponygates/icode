# 一键自动更新模型功能

## Goal

点击模型刷新按钮后，系统自动：
1. 从各provider的 `/v1/models` API 获取实时模型列表
2. 从各provider的官网文档页(llms.txt / API文档)获取补充模型信息(上下文长度、能力、定价)
3. 对比内置列表，自动**新增**官网有但内置没有的模型
4. 自动**标记**官网已下架(内置有但API/文档已无)的模型
5. 将更新结果持久化到磁盘，重启后仍生效
6. UI显示更新摘要："新增3个模型，标记下架2个模型"

## Scope / Non-goals

**包含:**
- 10个现有provider的自动更新(deepseek/zhipu/kimi/openrouter/volcengine/tencent/huawei/scnet/nvidia/anthropic)
- 官网文档页HTML抓取+解析(优先llms.txt等纯文本页面)
- 模型diff逻辑：新增/下架检测
- Desktop/SimpleUI/TUI 三个客户端的更新摘要展示
- 磁盘缓存+config持久化

**不包含:**
- 自动定时刷新(仅手动触发)
- 模型定价信息的自动更新(定价频繁变化，暂不自动同步)
- 新provider的自动发现(需手动注册)
- JS渲染页面的无头浏览器抓取(成本太高)

## Current State And Constraints

### 现有架构
- `pkg/modelupdate/service.go` — 核心更新服务，`knownFetchers` 从10个provider的API `/v1/models` 获取模型ID列表
- `fetchOpenAICompatModels()` — 通用OpenAI兼容API抓取，仅获取模型ID/name，**无上下文长度、能力、定价**
- `fetchOpenRouterModels()` — OpenRouter专用，获取context_length+pricing
- `fetchAnthropicModels()` — Anthropic专用，需特殊auth header
- `ProviderUpdate` 结构体 — 仅记录 Name/Success/Count/Source/Models/Error，**无diff信息**
- `BaseProvider.SetModels()` — 运行时更新provider内存中的模型列表
- 三级fallback: API fetch → disk cache → provider builtin
- `CacheEntry` — 磁盘缓存 `~/.icode/cache/{provider}.json`，24小时TTL

### 关键约束
- 官网多为JS渲染页面，直接HTTP GET只能获取HTML骨架
- 各provider的 `/v1/models` API 返回数据质量参差不齐：大部分只返回ID，不含上下文/能力
- 部分provider API需认证(Anthropic需x-api-key)，无key时返回401/403
- `ModelInfo` 结构体已有完整字段(ContextWindow/MaxOutputTokens/Capabilities/Plans/SupportsVision)
- 内置模型列表(provider .go文件)包含丰富的上下文/能力/定价信息，是"权威"元数据来源
- 磁盘缓存 `CacheEntry` 已有完整 `ModelInfo` 序列化能力

## Design

### 核心思路：API ID列表 + 内置元数据 富化 + 文档补充

**不采用**"纯官网抓取"方案(JS渲染问题无法解决)，而是：

1. **API获取ID列表**（现有逻辑） → 得到该provider当前可用的所有模型ID
2. **内置列表富化** → 用provider .go文件中的丰富元数据(上下文/能力/定价)填充API返回的骨架
3. **文档页补充** → 对有llms.txt或API文档页的provider，抓取补充信息(新增模型的上下文长度等)
4. **Diff检测** → 对比API返回的ID集合 vs 内置列表的ID集合
   - API有但内置没有 → **新增模型**，用API+文档数据构造ModelInfo
   - 内置有但API没有 → **下架模型**，标记`Deprecated: true`

### 1. 增强ProviderUpdate结构体

```go
type ProviderUpdate struct {
    Name    string            `json:"name"`
    Success bool              `json:"success"`
    Count   int               `json:"count"`
    Source  string            `json:"source"`
    Models  []types.ModelInfo `json:"models"`
    Error   string            `json:"error,omitempty"`
    // NEW: diff summary
    Added   []types.ModelInfo `json:"added,omitempty"`
    Removed []string          `json:"removed,omitempty"`  // model IDs no longer in API
}
```

### 2. 增强knownFetchers：添加文档URL配置

为每个fetcher添加可选的`docURL`字段，指向llms.txt或API文档页：

```go
type modelFetcher struct {
    name    string
    docURL  string   // e.g. "https://open.bigmodel.cn/llms.txt"
    fetch   func(ctx context.Context, cacheDir string) ([]types.ModelInfo, error)
}
```

各provider文档URL(优先llms.txt，次选API文档页)：
- openrouter: `https://openrouter.ai/llms.txt` (已知可用)
- deepseek: `https://api-docs.deepseek.com/llms.txt` (需验证)
- zhipu: `https://open.bigmodel.cn/llms.txt` (需验证)
- kimi: `https://platform.moonshot.cn/llms.txt` (需验证)
- anthropic: `https://docs.anthropic.com/llms.txt` (需验证)
- volcengine: 无(全JS渲染)，跳过文档补充
- tencent: `https://cloud.tencent.com/llms.txt` (需验证)
- huawei: 无(全JS渲染)，跳过文档补充
- scnet: 无，跳过
- nvidia: `https://build.nvidia.com/llms.txt` (需验证)

> 注：如果llms.txt不存在(404)，优雅降级——仅使用API数据。

### 3. 实现文档页抓取 `fetchDocModels()`

```go
func fetchDocModels(ctx context.Context, docURL string) (map[string]DocModelInfo, error)
```

- HTTP GET docURL，解析纯文本/Markdown格式的模型列表
- 提取模型ID→上下文长度/能力映射
- 返回 `map[string]DocModelInfo` 供富化使用
- 404/超时 → 返回空map，不影响主流程

### 4. 实现Diff逻辑 `compareModels()`

```go
func compareModels(builtin []types.ModelInfo, fetched []types.ModelInfo) (added []types.ModelInfo, removed []string)
```

- `builtin`: provider .go文件中的内置模型列表
- `fetched`: API返回的模型列表(已富化)
- 新增: fetched中有但builtin中没有的ID
- 下架: builtin中有但fetched中没有的ID

### 5. 增强 UpdateAll/UpdateOne 流程

```
UpdateAll() per provider:
  1. 获取内置列表: provider.ListModels() → builtinModels
  2. API获取: fetcher.fetch() → fetchedModels (可能只有ID)
  3. 文档补充: fetchDocModels(docURL) → docInfo (可选)
  4. 富化: mergeModelInfo(fetchedModels, builtinModels, docInfo)
     - 对fetched中每个模型，先在builtin中查找匹配ID
     - 找到 → 继承builtin的上下文/能力/定价
     - 未找到 → 用docInfo填充，否则保留API骨架
  5. Diff: compareModels(builtinModels, enrichedModels) → added, removed
  6. 对removed中的模型，标记 Deprecated (而非删除)
  7. 合并: enrichedModels + 标记Deprecated的builtin模型 → finalModels
  8. 推送到provider: SetModels(finalModels)
  9. 写入磁盘缓存
  10. 构造ProviderUpdate{Added, Removed}
```

### 6. ModelInfo添加Deprecated字段

```go
type ModelInfo struct {
    // ... existing fields ...
    Deprecated bool `json:"deprecated,omitempty"` // model no longer available via API
}
```

下架模型不删除，只标记`Deprecated: true`，UI中显示⚠️图标和"已下架"标签，仍可手动选择使用(以防用户有历史会话引用)。

### 7. 持久化策略

现有机制已够用：
- `writeCache()` → `~/.icode/cache/{provider}.json` (已有)
- `SetModels()` → provider内存更新 (已有)
- 新增: 将diff结果写入 `~/.icode/cache/update-history.json`，记录每次刷新的新增/下架

### 8. UI更新摘要

**Desktop ModelsPage:**
- `handleRefresh()` 调用 `POST /api/models/refresh`
- 解析返回的 `results[].added/removed`
- 显示toast: "✅ 新增 3 个模型 | ⚠️ 2 个模型已下架"
- 下架模型在列表中显示⚠️图标+灰色文字+"已下架"标签

**SimpleUI:**
- `refreshModels()` 后解析结果，弹出alert/toast显示摘要

**TUI:**
- `/models refresh` 命令输出diff摘要

## Risks And Compatibility

1. **llms.txt可用性不确定** — 大部分provider的llms.txt URL是推测的，可能404。缓解：fetchDocModels()优雅降级，404/超时不影响主流程
2. **API无认证返回401** — Anthropic等需要API key才能列出模型。缓解：现有逻辑已有fallback(cache→builtin)
3. **API返回模型不全** — 部分provider的/v1/models不返回所有模型(如华为)。缓解：不将"API中没有"作为下架的唯一判据，仅当连续2次刷新都无才标记Deprecated
4. **Deprecated字段向后兼容** — `json:"deprecated,omitempty"` 确保旧客户端忽略该字段
5. **SimpleUI内嵌JS** — 反引号需转义为\u0060，新增JS需注意
